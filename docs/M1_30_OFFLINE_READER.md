# Offline 30-title EN/RU atlas from retained normalized data

**UNPUBLISHED LOCAL READER — NOT PAGES / NOT LIVE.** Advances #12 and complements the pinned 30-title normalized candidate in [M1_30_RETAINED_CANDIDATE.md](M1_30_RETAINED_CANDIDATE.md).

The reader is a single standalone HTML file, generated without an API call or external assets from the repository-retained exact-byte candidate. It offers 30 selected titles across English/Russian Wikipedia, 35 observed UTC dates each (1,050 request values), a numeric final-week difference against the **median of four earlier seven-day totals**, search/edition filtering, keyboard-selectable ordering by absolute weekly difference, signed increase/decrease or final complete-week request volume, expandable 35-day exact-value tables, two-series same-window comparisons (including a direct “Compare this article” shortcut on every card that selects its stable page ID and focuses the second selector), a downloadable exact 35-day paired CSV (UTC date, stable local IDs, request counts, dataset and method), a zero-based side-by-side five-week comparison chart with a shared scale and an exact accessible weekly table plus a keyboard-expandable 35-row A/B daily table, and dataset/method/ID-bound URL restoration. The CSV link appears only for two distinct valid histories and needs JavaScript. It is generated offline from the same pinned daily values and never requests a server. Every history and table exists in static HTML without JavaScript; interactive filtering and comparison need JavaScript.

**Export the visible discoveries:** With JavaScript enabled, **Download visible 35-day CSV** exports the exact dated request counts for **only the currently visible titles** after search and edition filtering, in the current card-sort order. The file has one header and up to 1,050 rows (30 selected titles × 35 UTC dates), with `utc_date,project_page_id,requests,dataset_id,method_version` columns. The page ID is the existing stable local `(project,page_id)` key; no guessed title or cross-language identity is introduced. The CSV is built entirely from the same validated embedded observations, with no network requests, rounding or freshness claims. Empty results hide and clear the download; invalid/non-integer values and unrecognized IDs fail closed. The existing *paired* 35-day export remains separate. With JavaScript disabled, all underlying exact tables remain readable and the interactive export is unavailable.

From a clean checkout, using **Python 3.10+**:

```sh
python -m tools.m1_30_retained_candidate
python -m unittest tests.test_m1_30_retained_candidate tests.test_m1_30_reader -v
python -m tools.m1_30_reader --output /tmp/dayflare-30-offline.html
# Open the resulting new HTML locally. An existing destination is rejected.
```

**Russian title discovery:** The search field accepts common `е`/`ё` spelling variants, including decomposed Unicode spellings, for matching selected Russian titles (for example `черная дыра` can find `Чёрная дыра`). This normalization is **search-only**: the keyboard input and exact shared `q` value are preserved, and the recorded article title, `(project,page_id)` identity, data, source evidence, edition filter, and numeric ordering are unchanged. It is not general fuzzy matching, transliteration or identity inference. The field includes a visible hint; no-JavaScript exact tables are unchanged.

**Distinct measures and ordering:** The default card order ranks absolute differences between the final seven-day total and the median of the four preceding complete weeks. Signed increase/decrease ordering moves the highest/lowest differences first. **Most requests in last complete UTC week** sorts by that same last seven-day total, independent of whether its change was positive or negative. Equal-volume ties retain the original deterministic card order. This is request volume, **not** growth or a rising/returning/fading classification. The volume sort is also preserved in dataset/method-bound comparison URLs and checked against the exact printed total. With JavaScript disabled, all cards remain visible in the original absolute-difference order.
